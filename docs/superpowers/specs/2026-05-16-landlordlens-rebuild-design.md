# LandLordLens — Full Rebuild Design Spec

**Date:** 2026-05-16  
**Status:** Approved  
**Author:** Connor Simmons

---

## Overview

A complete rebuild of LandLordLens from the ground up. The goal is a clean, scalable foundation that eliminates all current tech debt, production blockers, and architectural compromises — while preserving every existing feature and the existing Supabase project (no data migration required).

**What changes:** Everything — framework, build tooling, project structure, API layer, testing setup.  
**What stays:** Supabase project, Stripe products/prices, all features, subscription tier model.

---

## Decisions Made

| Dimension | Decision | Rationale |
|---|---|---|
| Platform | Web only | No mobile for foreseeable future; removes React Native Web complexity |
| Framework | Next.js 15 App Router | Full-stack, Vercel-native, Server Components eliminate most loading states |
| Structure | Turborepo monorepo | Enforced package boundaries; ready for future services without rewriting |
| API layer | tRPC | End-to-end type safety; procedure-based; lives in shared package |
| Database ORM | Drizzle | Lightweight, SQL-like, schema-as-code, no Prisma/RLS friction |
| Styling | Tailwind CSS + shadcn/ui | Industry standard for Next.js; consistent component library |
| Email | Resend + React Email | Fixes critical production blocker (no email service) |
| Testing | Vitest + Playwright | Vitest replaces Jest (faster, native TS); Playwright for E2E |
| Deployment | Vercel only | Eliminates Render vs Vercel confusion; single target |

## Package Specifications

### `packages/db`

**Purpose:** Single source of truth for the database schema and all database access.

**Contents:**
- `schema/` — one Drizzle schema file per domain (`properties.ts`, `tenancies.ts`, `compliance.ts`, `expenses.ts`, `documents.ts`, `inspections.ts`, `maintenance.ts`, `profiles.ts`)
- `migrations/` — versioned SQL migration files generated by Drizzle Kit
- `client.ts` — Drizzle client singleton using `DATABASE_URL` (Supabase direct connection string)
- `helpers/` — shared query utilities (pagination, soft-delete, UUID generation)

**Key schema domains:**
- `profiles` — extends Supabase `auth.users` with subscription tier, Stripe IDs
- `properties` — property records with compliance state (JSON), status, user_id FK
- `tenancies` — tenancy records linked to properties and tenants
- `compliance` — compliance items (EPC, Gas Safety, HMO, Right to Rent, Deposit) per property
- `documents` — document metadata with Supabase Storage URLs
- `inspections` — inspection records with findings
- `maintenance` — maintenance requests with status workflow
- `expenses` — expense records with categories for tax reporting

**Constraints:**
- All primary keys are UUIDs
- All tables include `created_at` and `updated_at` timestamps
- Soft deletes on properties and tenancies (`deleted_at`)
- RLS remains enabled on all tables in Supabase. Drizzle queries run server-side via service role (bypasses RLS intentionally — auth is enforced at the tRPC middleware layer instead). The Supabase anon client is used directly only for Storage (file uploads/downloads) where RLS bucket policies apply.

**Schema bootstrap:**
The existing Supabase schema is pulled into Drizzle via `drizzle-kit introspect` at the start of the build. This generates the initial schema files from the live database, avoiding manual re-declaration of all tables.

### `packages/api`

**Purpose:** All tRPC procedures. The only package that imports from both `packages/db` and `packages/auth`.

**Contents:**
- `routers/` — one router file per domain:
  - `properties.ts` — CRUD + compliance summary
  - `tenancies.ts` — tenancy lifecycle
  - `compliance.ts` — compliance items CRUD + deadline alerts
  - `expenses.ts` — expense CRUD + categorisation
  - `documents.ts` — document metadata CRUD
  - `inspections.ts` — inspection workflows
  - `maintenance.ts` — maintenance request lifecycle
  - `analytics.ts` — portfolio analytics + reporting queries
  - `admin.ts` — admin-only procedures (user management, audit log)
  - `services.ts` — services marketplace
- `middleware/` — tRPC middleware:
  - `auth.ts` — verify Supabase session on every protected procedure
  - `subscription.ts` — tier enforcement (reads profile, checks limits)
- `root.ts` — merges all routers into the app router
- `trpc.ts` — tRPC instance creation + context definition

**Subscription enforcement:**
```typescript
// Enforced via middleware on relevant procedures
const canAddProperty = createSubscriptionGuard({
  check: (profile, db) => countUserProperties(profile.id, db) < TIER_LIMITS[profile.tier].properties
})
```

### `packages/auth`

**Purpose:** All Supabase auth logic. Consumed by `packages/api` and `apps/web`.

**Contents:**
- `server.ts` — Supabase server client factory (uses service role key)
- `browser.ts` — Supabase browser client factory (uses anon key)
- `middleware.ts` — Next.js middleware export (protects `/dashboard` and all nested routes)
- `session.ts` — `getSession()`, `getCurrentUser()`, `requireUser()` helpers
- `roles.ts` — role type definitions and guards (`isAdmin()`, `isLandlord()`)

**Purpose:** All Stripe and subscription logic. No UI — pure business logic.

**Contents:**

- `tiers.ts` — tier definitions and limits:
  ```typescript

    business:     { properties: 50,  monthlyPriceId: '...', yearlyPriceId: '...' },
  ```

- `webhooks.ts` — webhook event handler (syncs subscription state to DB via `packages/db`)

## Data Flow

### Authenticated page load (Server Component)
```
Browser request → Next.js middleware (packages/auth) checks session
→ RSC renders, calls tRPC server caller directly (no HTTP)
→ tRPC procedure runs auth + subscription middleware
→ Drizzle queries Supabase Postgres
→ Data returned to RSC → HTML streamed to browser
```

### Client mutation (form submit)
```
Client Component → tRPC client (React Query useMutation)
→ POST /api/trpc/[procedure]
→ tRPC handler → auth middleware → procedure → Drizzle → Supabase
→ Response → React Query invalidates relevant queries → UI updates
```

### Stripe webhook
```
POST /api/webhooks/stripe → verify signature
→ packages/billing webhook handler
→ Update profiles table via packages/db
→ 200 OK
```

## Testing Strategy

### Unit tests (Vitest)
- Location: `packages/*/src/__tests__/`
- Scope: Pure business logic — tier limits, subscription guards, session helpers, query helpers, compliance deadline calculations
- No database, no network — fully isolated
- Run: `pnpm test` (Turborepo runs all packages in parallel)

### Integration tests (Vitest + Supabase CLI)
- Location: `packages/api/src/__tests__/integration/`
- Scope: tRPC procedures against a real local Supabase instance
- Setup: `supabase start` spins up local Postgres with schema applied via Drizzle migrations
- Tests: Auth flows, CRUD operations, tier enforcement, webhook handler
- Run: `pnpm test:integration`

### E2E tests (Playwright)
- Location: `apps/web/e2e/`
- Scope: Critical user journeys in a real browser
- Journeys covered:
  1. Sign up → receive verification email → verify → complete onboarding
  2. Add property → add tenancy → view compliance dashboard
  3. Compliance item expiring → alert shown → mark renewed
  4. Upgrade plan via Stripe test mode → property limit increases
  5. Section 8 wizard → generated document downloadable
  6. Admin: view all users, view audit log
- Run: `pnpm test:e2e`

### CI (GitHub Actions)
- On every push: type-check, lint, unit tests
- On every PR: all of the above + integration + E2E
- Turborepo cache: only affected packages re-tested

- `vercel.json` at repo root points to `apps/web`

## Production Blockers — All Resolved

| Blocker | Resolution |
|---|---|
| `/api/seed` exposed in production | Route does not exist in rebuild |
| No email service | Resend + React Email in `apps/email` |
| Stripe env var name mismatch | Standardised names throughout |
| Build output path incorrect | Vercel handles Next.js build automatically |
| CSP unsafe-inline | Next.js nonce-based CSP via middleware |
| Sentry at 100% sampling | Fixed to 10% in Sentry config |
| No email verification | Verification flow built into auth from day one |

## What Is NOT Carried Forward

- React Native Web (dropped — web only)
- Webpack 5 + Babel (replaced by Next.js/Turbopack)
- Express server (replaced by Next.js Route Handlers)
- Mixed `.js` / `.ts` files (TypeScript throughout)
- Winston logger (Next.js + Sentry handles this)
- Swagger/OpenAPI (tRPC provides type safety instead)
- Render deployment config (`render.yaml` deleted)
- `.bak` files
- Jest + Babel test setup (replaced by Vitest)
- `react-native` in prod dependencies
